== Game Lore
Cave Mummies is a **2D arcade/survival** game that creates a fun and enjoyable
experience during gameplay, through **unlimited** game time with an infinite
game mode that features the main character **Wil**.
Wil is an anthropomorphic creature that appeared one day on his owner's
backyard as a baby. Since then, his owner has taken care of him.
Wil is stranded in a cave where his owner went missing. He's in the search for
him, but encounters himself surrounded by hordes of **mummies** that are
desperate to take him down.
Before Wil's owner went on searching for treasure in the caves, he left Wil a
firearm so he could protect himself against any danger. Since it has been a
while since Wil has seen his owner, he starts his journey looking for him taking
the weapon he was given.

Wil does not know when the hordes of mummies will stop, but he knows he has to
survive to see his owner again. Wil discovers they only perform
**melee attacks**, therefore he must take advantage of his ranged weapon.

== Game Specification
Cave Mummies is a single-player desktop video game which is built on 
_Cpass:[++]_ and _NASM_ (x86_64 Assembly). It utilizes Raylib as its base 
graphics library, and relies on it for all graphic and input actions in the
game. The game features code implementations in assembly, compilable only with 
NASM compiler. These code implementations are only for Linux-based systems. 
The game is made fully with _Cpass:[++]_ in its Mac release.

The core mechanic of the game is time-based survival with score progression.
The player is intended to survive as long as possible. The player will
accumulate a higher score based on elapsed time and the number of mummies
defeated. The recorded highest game score will be the one while the program
is running. Game scores are not saved or stored when the program is closed.

=== Key features
- Static arena gameplay
- Enemy waves with multiple difficulty levels (speed and resistance)
- Player's weapon with limited ammunition
- Elapsed time clock for game sessions
- Scoring system with high-score tracking
- Minimalistic menu interface

== How to Play
image:doc-assets/gameplay_preview_one.png[Gameplay preview, align=center]

At first, the player must navigate through the presented main menu. 
The player can navigate the menu utilizing `W` / `ARROW_UP` keys for going
**upward**, and `S` / `ARROW_DOWN` keys for going **downward**.
The player can select an  option by pressing the `RETURN` key or using the 
`MOUSE_LEFT_CLICK` key anywhere on the screen.

These navigation instructions apply to all menus presented during the
game's lifetime. Following these navigation instructions, the player
should select the **Start** option, which is first in the menu. Once the player
selects that option, the game will initiate gameplay.

The game provides the following key control interface for the player to use:

- **Movement**:
- Left: `A` / `ARROW_LEFT`
- Right: `D` / `ARROW_RIGHT`
- **Run**: `LEFT_SHIFT` (can only be used simultaneously with movement keys)
- **Jump**: `SPACE_BAR` / `W` / `ARROW_UP`
- **Reload**: `R` / `MOUSE_LEFT_CLICK`
- **Shoot**: `MOUSE_LEFT_CLICK`
- **Pause**: `ESC` (can only be used during gameplay)
- **Music**: `M` (toggles the background music)

===== Note:
This game features compatibility with the Arduino platform enabling movement
with the joystick accessory. The player can move the its character utilizing a
joystick-controlled release and a connected Arduino device with a joystick
accessory. Movement is just as in many other game titles, rolling the joystick
horizontally to the sides moves the player in that direction. Rolling the
joystick upward makes the player jump. Running can be done by pressing the
joystick button down.

The player must aim at incoming enemies which will try to follow him/her, and
**shoot** them to take them down. Surely shooting with a weapon which has
unlimited bullets as ammunition is **satisfying**, but there is a limit to how
many bullets may be loaded into the weapon.
The weapon should only yield twelve bullets at a time. After the remaining
loaded bullets are used, the player must wait until the weapon is reloaded.
Reloading may take up to two seconds and can only occur once the magazine is
empty.

=== How to Win
To win the game is actually a matter of the player's want. The game by itself
does not have a finish line, or a proper end screen. Rather, the game continues
indefinitely until the player ultimately fails to avoid the incoming waves of
enemies, and dies.

To increase the current game score, only two factors can contribute to it:
time elapsed and enemies killed. Elapsed time, as its label implies, refers
to the time elapsed since the start of the gameplay. Each second elapsed
accounts for one extra point to the current game score. A greater enemy kill
count should algo grant a better score. For each enemy killed, 10 points
are added to the score. The player starts out with only two jumps available from
the moment they are standing on the floor tile. Killing enemies increases the
amount of jumps the player can perform. This jump count can be accumulated,
therefore, the player can accumulate as many jumps as enemies killed.

The player's goal is to survive as long as possible without being touched by an
enemy. The game score may indicate a degree of "winning", in the sense that a
higher score may indicate gamer prowess.

In both the paused menu, and game over screen, an option to go back to
the main menu is available. This option records current game score if its
the highest ever achieved.

[[gameplay_summary]]
=== Gameplay Summary
The gameplay mechanics can be summarized in the key points of the following
list. The following list summarizes the main gameplay mechanics:

- Survive waves of enemies appearing from the sides of the stage
- Avoid running out of loaded bullets in your weapon
- Aim and shoot at enemies to survive
- Avoid direct contact with enemies
- The longer you stay alive, the higher your score
- Kill as many enemies as possible to get a better score
- Wisely manage your accumulated jump count
- Staying in the air can prevent enemies from reaching you
- A high-score tracker records your best survival time

=== Disclaimer
Before attempting to build the project, make sure the required dependencies are
on your machine, and that their paths are reachable. Using the `make help`
command, an interface is displayer with all available targets provided by the
Makefile. Make sure to follow the set interface.

The following indications are focused on MacOS and Linux-based systems
specifically. Support for machines with Windows operating system, or other
operating systems is not readily supported, nor there is documentation for
those systems relating to this project in this document.

=== Instructions
Previous to the building instructions, there is the `make raylib` command, which
clones and builds the raylib dependency for this project to build adequately.
If you have an Arduino device with a joystick accessory, you can opt to build
a release version to play with a joystick. This option is done with the
`make release_joystick` command. The rest of this section orients itself to a 
keyboard-controlled release version of the game, but everything mentioned here
still applies.

Starting off, open a terminal window and direct yourself to the root of this
project. There, to build the game run the `make` command for a basic build.
This action will compile the source code in a directory named `build/` in the
current project, and link the compiled code into an executable named
`Cave mummies` in a `bin/` directory.

The previous command mentioned provides a standard debug compilation for the
game, but also a `make release` command is provided by the Makefile interface
to compile a release version of the game. The created executable oriented
for an optimized release version of the game.

To clear any compiled files and executables, utilize the `make clean`
command. This command will remove the `build/` and `bin/` directories in one
action, but will not remove the `libs/raylib/` directory. To remove the raylib 
dependency directory, manually delete the `libs/` folder.

[[usage]]
=== Usage
The Makefile interface provides the `make run` command, which should be used to
run the game. If no compiled executable is available, the command will compile 
the game using `make`.

Another alternative, is to direct yourself to the `bin/` directory in the root
of the project and executing the executable file manually. A desktop shortcut
can also be created using the executable file located inside the `bin/` 
directory.

== Dependencies
To compile the game utilizing its build features, the following dependencies
must be present on your machine:

- gpass:[++] compiler (C++ compiler)
- NASM (ASM compiler for Linux-based systems)
- Git (version control tool)
- Make (Build tool)
- cpplint (Linting tool required for 'make lint')
- Doxygen (Documentation tool required for 'make doc')

All of these dependencies are to be installed suited to your operating system.
There is no guide on how to install these besides this requirement list.
